# Research

## Surface research

- **Scope**: Read-only diagnosis of startup/readiness and a bounded storage architecture, including cross-harness retention and old-transcript formats.
- **Sources inspected**: Arden runtime/storage and live state; current Letta Code, Codex, Hermes Agent, and OpenCode storage plus native export/import paths; three earlier Codex tasks; Harbor ATIF v1.7; Letta Trajectory v1 and its published bounds.
- **Observations**: API readiness is a single pre-`yield` critical path. The scheduler can begin due work before that path finishes.
- **Negative evidence**: Automation bodies are detached tasks and do not directly block `scheduler.start()`; the delay comes from startup ordering and shared projection/storage work, not from awaiting each automation to completion.

## Conflicts and gaps

- The automation contribution is proven at the ordering/race level, but exact seconds per contender require phase/lock timing instrumentation.
- No destructive cleanup or cold-start reproduction was run against live data.
- None of the reviewed harnesses uses normalized trajectories as authoritative cold storage. Letta adds a derived view; Codex keeps native rollouts; Hermes and OpenCode export full native session shapes.
- No Arden conversion benchmark exists yet. ATIF and Letta's published token counts cannot predict compressed on-disk bytes or restore/search cost.
- The current session model has archive state but no explicit protected/pinned flag; a quota must not infer protection from age alone.

## Supporting material

- Live disk had only 13 GiB free (`df -h`), so an 8 GiB `VACUUM INTO`/atomic swap needs a strict space preflight and likely preliminary reclaim/archive work.
- Wiki footprint is small (27 MiB memory tree, 2,301 history files, 73 pages); repeated full projection is expensive because it performs index/health fixed-point work, not because canonical pages are large.
- Recent logs also show projection conflicts (`WikiSnapshotChangedError`, `RevisionConflictError`) while the wiki changes concurrently, supporting serialization/coalescing after readiness.
