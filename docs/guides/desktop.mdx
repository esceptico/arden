## Overview

The desktop app is the primary arden client. It connects to the local server over HTTP/SSE and renders chat, streaming activity, approvals, memory views, settings, automations, and sandboxed HTML widgets.

## Run from source

```bash
cd apps/desktop
bun install
bun run dev
```

The app connects to `http://localhost:6877` by default. Start the server first with `arden-server serve` or `just server`.

## Connect

On first launch, enter:

- **Server URL**: usually `http://localhost:6877`
- **API key**: the one-time key printed by `arden-server serve`

The API key is stored locally. When the OS supports Electron `safeStorage`, the desktop app encrypts it before persisting.

## Home

Home is the app's landing surface. It's reachable from the sidebar and shown whenever no session is open. It has a composer, the **focus set** (every area's one ask in a single list), and the **areas strip**. Opening an area takes you to its room; see the [Areas guide](/guides/areas).

## Main surfaces

- **Home**: the composer, focus set, and areas strip. The default landing surface.
- **Area rooms**: an area's open loops, its agent's status and one ask, related areas, activity, and a scoped composer.
- **Chat**: streaming assistant responses, tool calls, attachments, and rendered widgets.
- **Approvals**: review mutating or risky tool calls before execution.
- **Activity traces**: inspect tool calls, workflow agents, background work, and run lifecycle events.
- **Memory**: browse and edit managed wiki pages, inspect links, records, and history, and review maintenance changes.
- **Automations**: view scheduled, channel, area-agent, and system automations, edit and run them, and inspect run history.
- **Settings**: configure providers, tools, MCP servers, directives, model selection, and local client preferences.
